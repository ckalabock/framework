# Система учёта посетителей организации

Приложение для регистрации посетителей, выдачи пропусков и учёта посещений. Проект развивался последовательно: ПР1 — начальный сценарий, ПР2 — работа с коллекциями и JSON, ПР3 — объектная модель, ПЗ5–ПЗ6 — веб-приложение на Django с SQLite, HTML-интерфейсом и JSON API.

## Возможности

- добавление, поиск и сортировка посетителей;
- добавление сотрудников и изменение их доступности;
- выдача пропуска посетителю и проверка срока его действия;
- создание посещения и проверка допуска;
- запрет двух активных посещений одного посетителя на одну дату;
- просмотр посещений на дату и отмена посещения;
- сохранение всех данных между запусками в JSON.

## Веб-версия (практики №5–6)

Добавлена Django-веб-версия проекта в пакетах `visitor_project/` и `webapp/`:

- SQLite-модели `VisitorRecord`, `EmployeeRecord`, `AccessPassRecord`, `VisitRecord`;
- миграции и ограничения базы данных, включая запрет двух активных посещений на одну дату;
- авторизация пользователей через встроенный Django LoginView;
- HTML-интерфейс: списки сущностей и формы создания посетителей, сотрудников, пропусков и посещений;
- JSON API: `GET /api/visitors/` и `GET /api/visits/`;
- защита POST-форм CSRF и проверка данных через Django Forms;
- CSS-оформление и адаптивная сетка без внешних сервисов.

## Объектная модель

- `Visitor` — посетитель: идентификатор, ФИО и документ.
- `Employee` — принимающий сотрудник: идентификатор, ФИО, отдел и доступность.
- `AccessPass` — пропуск: номер, владелец и срок действия.
- `Visit` — посещение: посетитель, сотрудник, пропуск, дата, цель и статус.

Объект `Visit` содержит связанные объекты `Visitor`, `Employee` и `AccessPass`. Метод `Visit.is_allowed()` определяет возможность допуска, а `Visit.cancel()` отменяет запись.

## Структура проекта

```text
pr1/
├── main.py             # точка запуска, консольное меню
├── models.py           # классы Visitor, Employee, AccessPass, Visit
├── visitors.py         # функции работы с коллекцией посетителей
├── employees.py        # функции работы с сотрудниками
├── passes.py           # функции работы с пропусками
├── visits.py           # функции создания и отмены посещений
├── storage.py          # загрузка и сохранение JSON
├── utils.py            # безопасный ввод данных
├── data/               # JSON-файлы приложения
├── tests/              # тесты pytest
├── requirements.txt    # pytest и flake8
└── docs/               # описания выполненных практик

Веб-часть проекта также содержит `manage.py`, `visitor_project/`, `webapp/`, `templates/` и `static/`.
```

## Формат данных

Данные хранятся в каталоге `data/` в формате JSON. В файлах связей используются идентификаторы: например, в `visits.json` хранятся `visitor_id`, `employee_id` и `pass_id`. При запуске `storage.py` восстанавливает по ним связанные объекты Python.

## Запуск

```powershell
python main.py
```

Запуск веб-версии:

```powershell
python manage.py migrate
python manage.py createsuperuser
python manage.py runserver
```

Откройте `http://127.0.0.1:8000/login/`. После входа доступны интерфейс и API: `/api/visitors/` и `/api/visits/`.

## Тестирование и качество кода

Установить инструменты разработки:

```powershell
python -m pip install -r requirements.txt
```

Запустить тесты:

```powershell
pytest -v
```

Проверить стиль кода:

```powershell
flake8 .
```
