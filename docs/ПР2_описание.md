# ПР2 — продолжение проекта: коллекции, функции, циклы и JSON

## Что требовала практика

ПР2 требовала переработать сценарий ПР1 в функциональную консольную программу. В проекте должны быть коллекции, циклы, функции, несколько модулей, обработка исключений, JSON-хранение, аннотации типов, тесты `pytest`, проверка `flake8` и актуальный `README.md`.

## Что добавлено

- Коллекции для работы с несколькими посетителями, сотрудниками, пропусками и посещениями.
- Консольное меню с операциями просмотра, добавления, поиска, сортировки, регистрации и отмены посещений.
- Модули `visitors.py`, `employees.py`, `passes.py`, `visits.py`, `storage.py` и `utils.py`.
- Безопасный ввод: неверные числа, даты и ответы не завершают программу с ошибкой, а запрашиваются повторно.
- Хранение данных в `data/visitors.json`, `data/employees.json`, `data/passes.json` и `data/visits.json`.
- Загрузка и сохранение JSON через контекстные менеджеры `with open(...)`.
- Автоматические тесты в каталоге `tests/` и зависимости в `requirements.txt`.

## Что изменилось относительно ПР1

В ПР1 программа обрабатывала только одного посетителя за запуск. После ПР2 она поддерживает набор записей, выполняет поиск посетителя по части ФИО, выводит посетителей в сортированном виде, создаёт посещения на выбранные даты и сохраняет результат между запусками.

## Как проверить добавленные функции ПР2

Сначала откройте терминал в папке проекта и выполните:

```powershell
python main.py
```

Проверьте меню по порядку:

1. Нажмите `1`: программа должна вывести посетителей, отсортированных по ФИО.
2. Нажмите `2`: добавьте нового посетителя, документ, номер пропуска и будущую дату окончания пропуска. Затем снова нажмите `1` и убедитесь, что посетитель появился в списке.
3. Нажмите `3`: введите часть только что добавленного ФИО. Должна появиться найденная запись. Введите несуществующую строку — появится «Совпадения не найдены».
4. Нажмите `5`: добавьте сотрудника. Пункт `4` должен показать его в списке.
5. Нажмите `6`: выберите идентификатор сотрудника, ответьте `нет`. Повторный пункт `4` должен показать «недоступен».
6. Нажмите `7`: создайте посещение для посетителя и доступного сотрудника. Пункт `8` с той же датой должен вывести созданную запись.
7. Снова выберите `7` для того же посетителя и той же даты. Должно появиться сообщение о существующем активном посещении.
8. Нажмите `9`, укажите идентификатор посещения. Появится сообщение «Посещение отменено».
9. Ещё раз выберите `7` для этого посетителя и даты. Новая запись должна успешно создаться, потому что предыдущая отменена.
10. Завершите программу через `0`, запустите её снова и убедитесь пунктами `1`, `4` и `8`, что данные сохранились. Это проверка JSON.

После ручной проверки выполните:

```powershell
python -m pytest -v
python -m flake8 .
```

Ожидаемый результат: `5 passed`, а команда `flake8` не выводит замечаний. Для отладки поставьте breakpoint внутри `has_active_visit()` или `create_visit()` в файле `visits.py`, создайте посещение и пройдите строки пошагово.
