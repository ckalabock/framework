# Отчёт по практической работе №6 — Django-шаблоны

## Цель

Развить интерфейс ПР5 с помощью системы шаблонов Django и собственных статических файлов.

## Что требовалось и что выполнено

1. Создан общий `templates/base.html`; дочерние шаблоны используют `{% extends "base.html" %}`.
2. В базовом шаблоне определены блоки `{% block title %}` и `{% block content %}`.
3. Навигация вынесена в `templates/includes/navigation.html` и подключена тегом `{% include %}`.
4. View передают в шаблоны context: отдельные объекты, коллекции и счётчики.
5. В шаблонах показаны обращение к атрибутам (`{{ visitor.full_name }}`), циклы `{% for %}`, ветвления `{% if %}` и обработка пустых коллекций `{% empty %}`.
6. Использованы фильтры `default`, `date`, `upper`, `capfirst`.
7. В `webapp/urls.py` задан `app_name = "webapp"`; все URL имеют имена. В шаблонах ссылки формируются через `{% url "webapp:..." %}`.
8. Добавлены собственные static-файлы: `static/webapp/css/style.css`, `static/webapp/js/app.js`, `static/webapp/images/visitor-card.svg`. В `base.html` используется `{% load static %}`.
9. Страницы ПР5 переработаны в отдельные шаблоны списков и карточек; функции-генератора одной HTML-страницы нет.

## Проверка

```powershell
python manage.py check
python manage.py test webapp
```

Запустите сервер и откройте главную страницу. Проверьте единый стиль, навигацию, карточки и динамические ссылки. Временно очистите одну из коллекций в JSON только на копии файла: на соответствующем списке появится сообщение из `{% empty %}`; затем верните исходный файл.

## Результат

Интерфейс построен из переиспользуемых Django-шаблонов, URL не прописываются вручную, а оформление, изображение и JavaScript подключаются как static-ресурсы.
