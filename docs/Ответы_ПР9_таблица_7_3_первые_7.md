# ПР9: первые 7 показателей таблицы 7.3

Ниже приведён сценарий демонстрации преподавателю. Перед защитой выполните `python manage.py migrate` и `python manage.py seed_demo`.

## 1. Описание моделей и параметров полей

Открыть `webapp/models.py` и показать классы `Visitor`, `Employee`, `AccessPass`, `Visit`. Объяснить: `CharField` хранит строки ограниченной длины, `BooleanField` — признак доступности, `DateField` — дату. `blank=True` разрешает пустое значение при проверке формы, `default` задаёт значение по умолчанию, а `null` в проекте не нужен: пустые строки хранятся как `""`. Для изменения параметра изменить, например, `max_length`, затем выполнить `python manage.py makemigrations webapp` и `python manage.py migrate`.

Показать результат: после миграции схема таблицы обновляется, а существующие записи сохраняются.

## 2. Связи между моделями

Открыть поля `visitor`, `employee` и `access_pass` в `webapp/models.py`. Это `ForeignKey`: один посетитель может иметь несколько пропусков и посещений, один сотрудник — несколько посещений. `on_delete=PROTECT` запрещает удаление объекта, пока на него ссылаются записи. `related_name` задаёт обратное имя связи.

Выполнить:

```powershell
python manage.py shell
from webapp.models import Visit
visit = Visit.objects.select_related('visitor', 'employee', 'access_pass').first()
visit.visitor.full_name
visit.employee.full_name
visit.access_pass.number
```

## 3. Прямая и обратная связь

В той же shell показать `visit.visitor` и `visit.employee` — это прямая связь от посещения. Затем показать `visit.visitor.visits.all()` и `visit.employee.visits.all()` — обратные связи, созданные параметром `related_name`.

Если переименовать `related_name`, необходимо использовать новое имя во всех запросах и шаблонах. Например, `visitor.visits` заменится на указанное новое имя.

## 4. Создание и применение миграций

В редакторе открыть `webapp/models.py` и `webapp/migrations/0001_initial.py`. В терминале показать:

```powershell
python manage.py makemigrations webapp
python manage.py migrate
```

`makemigrations` сравнивает модели с состоянием миграций и создаёт Python-описание изменения схемы. `migrate` выполняет это описание в SQLite. Для демонстрации изменения можно добавить поле, создать новую миграцию, применить её и показать `python manage.py showmigrations`.

## 5. Создание объекта через ORM

В shell выполнить:

```python
from datetime import date
from webapp.models import Visitor
test_visitor = Visitor.objects.create(full_name='ORM-проверка', document='ORM-001')
test_visitor.full_name = 'ORM-проверка изменена'
test_visitor.save()
Visitor.objects.get(pk=test_visitor.pk).full_name
```

Объяснение: `create()` создаёт объект и сразу сохраняет строку в базе. Изменение атрибута в памяти не меняет БД до вызова `save()`; повторный `get()` подтверждает сохранённое значение.

## 6. Изменение существующего объекта

В shell получить запись, изменить поле и сохранить:

```python
employee = Employee.objects.first()
employee.is_available = not employee.is_available
employee.save(update_fields=['is_available'])
Employee.objects.get(pk=employee.pk).is_available
```

`update_fields` ограничивает UPDATE изменённым полем. До `save()` меняется только Python-объект, после `save()` — запись SQLite.

## 7. Удаление объекта через ORM

Для безопасной демонстрации создать отдельного посетителя без связанных объектов:

```python
temporary = Visitor.objects.create(full_name='Временная запись', document='DELETE-ME')
temporary.delete()
Visitor.objects.filter(full_name='Временная запись').exists()
```

Результат — `False`. Удаление посетителя, на которого ссылаются пропуск или посещение, будет запрещено `on_delete=PROTECT`; сначала нужно удалить или переназначить зависимые записи.

## Полезные команды защиты

```powershell
python manage.py showmigrations
python manage.py dbshell
python manage.py shell
```

В `dbshell` можно показать таблицы SQLite, а в `shell` — ORM-запросы и связанные объекты.
