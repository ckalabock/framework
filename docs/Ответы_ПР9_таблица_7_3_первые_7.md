# ПР9: точная демонстрация первых 7 пунктов таблицы 7.3

Важно: в методичке примеры называются `Room`, `User`, `Booking`, потому что предметная область примера — Roomly. В моём проекте предметная область другая, поэтому используются эквивалентные модели:

| Пример методички | Мой проект | Что показывать |
|---|---|---|
| `Room` | `Visitor` | посетитель и его поля |
| `User` | `Employee` | сотрудник и его поля |
| `Booking` | `Visit` | посещение и его связи |

В `webapp/models.py` в конце оставлены явные обозначения `Room = Visitor`, `User = Employee`, `Booking = Visit`, чтобы соответствие можно было объяснить преподавателю. Не надо утверждать, что проект буквально является Roomly: нужно сказать, что пример адаптирован под учёт посетителей.

## 1. Описание модели данных, изменение поля и миграция

Сначала открыть `webapp/models.py` и показать **все три основные модели**, которые требуются в вопросе: `Visitor` (аналог `Room`), `Employee` (аналог `User`) и `Visit` (аналог `Booking`). Дополнительно показать `AccessPass`, потому что он связан с посещением.

Объяснение полей:

- `Visitor.full_name` — `CharField(max_length=200)`, аналог названия объекта;
- `Employee.full_name`, `department`, `is_available` — данные сотрудника;
- `Visit.visit_date`, `purpose`, `status` — данные посещения;
- `blank=True` разрешает пустое значение в формах/валидации;
- `default` подставляет значение, если его не передали;
- `null` в этих моделях не используется: для необязательных строк хранится пустая строка.

Затем **обязательно изменить параметр поля**. Самый безопасный вариант — изменить `Visitor.document` с `max_length=50` на `max_length=80` в редакторе. После изменения выполнить:

```powershell
python manage.py makemigrations webapp
python manage.py migrate
```

В редакторе показать новый файл миграции `webapp/migrations/0002_*.py` и объяснить: `makemigrations` записывает изменение схемы, `migrate` применяет его к SQLite. После демонстрации можно оставить `80` — это рабочее изменение модели.

## 2. Создание связи между моделями

В `webapp/models.py` показать `ForeignKey` в `AccessPass` и `Visit`:

```python
visitor = models.ForeignKey(Visitor, on_delete=models.PROTECT, related_name="visits")
employee = models.ForeignKey(Employee, on_delete=models.PROTECT, related_name="visits")
access_pass = models.ForeignKey(AccessPass, on_delete=models.PROTECT, related_name="visits")
```

Объяснить: `ForeignKey` реализует связь «многие к одному», `PROTECT` не даёт удалить объект, на который ссылаются записи, `related_name` задаёт обратное имя. В shell показать `visit.visitor`, `visit.employee`, `visit.access_pass`.

```powershell
python manage.py shell
from webapp.models import Visit
visit = Visit.objects.select_related("visitor", "employee", "access_pass").first()
visit.visitor.full_name
visit.employee.full_name
visit.access_pass.number
```

## 3. Прямая и обратная связь

Прямая связь: `visit.visitor` и `visit.employee`.

Обратная связь задаётся `related_name`:

```python
visit.visitor.visits.all()
visit.visitor.access_passes.all()
visit.employee.visits.all()
```

Объяснить, что без `related_name` Django создал бы имя вида `visit_set`, а с ним код читается понятнее. При изменении `related_name` нужно изменить обращения во всех views, тестах и шаблонах.

## 4. Создание и применение миграций

Открыть модель и соответствующие файлы `webapp/migrations/0001_initial.py` и `0002_*.py`. В терминале выполнить:

```powershell
python manage.py makemigrations
python manage.py migrate
python manage.py showmigrations
```

`makemigrations` создаёт Python-файл описания изменения моделей. `migrate` выполняет миграцию в базе. В `showmigrations` у нужной миграции должна стоять отметка `[X]`.

## 5. Создание объекта через ORM

В Django Shell выполнить:

```python
from webapp.models import Visitor
test_visitor = Visitor.objects.create(full_name="ORM-проверка", document="ORM-001")
test_visitor.full_name = "ORM-проверка изменена"
test_visitor.save()
Visitor.objects.get(pk=test_visitor.pk).full_name
```

Объяснить: `create()` создаёт и сохраняет объект, изменение атрибута без `save()` меняет только память, `save()` записывает новое значение в SQLite, `get()` читает его обратно.

## 6. Изменение существующего объекта через ORM

```python
from webapp.models import Employee
employee = Employee.objects.first()
employee.is_available = not employee.is_available
employee.save(update_fields=["is_available"])
Employee.objects.get(pk=employee.pk).is_available
```

Показать старое и новое значение. Объяснить разницу между изменением Python-объекта и сохранением изменения в базе.

## 7. Удаление объекта через ORM

Для безопасной демонстрации создать отдельного посетителя:

```python
temporary = Visitor.objects.create(full_name="Временная запись", document="DELETE-ME")
temporary.delete()
Visitor.objects.filter(full_name="Временная запись").exists()
```

Результат — `False`. Затем объяснить `PROTECT`: посетителя, у которого есть пропуск или посещение, нельзя удалить до удаления зависимых записей.
