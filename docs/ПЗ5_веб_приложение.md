# Отчёт по практической работе №5 — основы Django

## Цель

Создать Django-проект и отобразить предметную область «Учёт посетителей организации» в браузере, не заменяя объектную модель ПР3 и JSON-хранилище.

## Что требовалось и что выполнено

1. Создан конфигурационный пакет `visitor_project/` и приложение `webapp/`.
2. В `visitor_project/settings.py` подключено приложение `webapp`, настроены каталог шаблонов и статические файлы. Для учебного запуска оставлены `DEBUG = True` и пустой `ALLOWED_HOSTS`.
3. В корневом `visitor_project/urls.py` подключён URLconf приложения через `include("webapp.urls")`.
4. В `webapp/urls.py` сделаны маршруты главной страницы, списков и карточек посетителей, сотрудников, пропусков и посещений. Для карточек применены динамические параметры `<int:..._id>`.
5. В `webapp/views.py` реализованы view-функции. Они читают JSON через `storage.py`, восстанавливают объекты `Visitor`, `Employee`, `AccessPass`, `Visit` и передают их в HTML через `render()`.
6. Реализована обработка отсутствующей записи: `find_by_id()` поднимает `Http404`.
7. Сделаны страницы со списками и деталями сущностей, а также навигация между ними.

## Важное ограничение этапа

На ПР5 не применялись Django ORM, миграции, SQLite, Django Forms, авторизация и формы создания записей. Это сознательное решение: данные продолжают храниться в `data/*.json`, а Django отвечает за маршрутизацию и вывод HTML.

## Проверка

```powershell
python manage.py check
python manage.py runserver
```

В браузере откройте `/`, `/visitors/`, `/visitors/1/`, `/employees/`, `/passes/`, `/visits/`. Затем откройте `/visitors/999999/`: должна отобразиться стандартная страница 404.

## Результат

Получено работающее Django-приложение с маршрутизацией, view-функциями и HTML-страницами. Существующая бизнес-модель и JSON-данные сохранены.
