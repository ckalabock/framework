# ПР9 — модели Django и ORM

## Что изменилось

Веб-приложение переведено с JSON-загрузки на Django ORM. В `webapp/models.py` описаны модели `Visitor`, `Employee`, `AccessPass` и `Visit`, соответствующие сущностям системы учёта посетителей.

Поля имеют подходящие типы (`CharField`, `BooleanField`, `DateField`), ограничения `max_length`, `blank`, `default` и явные связи. `AccessPass` связан с посетителем, а `Visit` — с посетителем, сотрудником и пропуском через `ForeignKey`. Для связей заданы `on_delete=models.PROTECT` и понятные `related_name`, чтобы защищать связанные записи и использовать обратный доступ (`visitor.visits`, `employee.visits`).

Создана миграция `webapp/migrations/0001_initial.py` и применена к `db.sqlite3`. Команда `python manage.py seed_demo` переносит демонстрационные записи из JSON в базу через ORM. JSON сохранён как исходный набор для повторяемого импорта, но веб-views теперь используют только `Model.objects`.

Представления используют `count()`, `all()`, `get_object_or_404()`, `select_related()` и обратные связи ORM. Шаблоны ПР5–ПР6 продолжают работать с объектами моделей без формирования HTML в Python.

## Команды проверки

```powershell
python manage.py makemigrations
python manage.py migrate
python manage.py seed_demo
python manage.py check
python manage.py test webapp
python -m pytest -v
python -m flake8 . --exclude=.venv
```

Старый файл `db.sqlite3.pre_pr9.bak` — резервная копия базы предыдущего этапа; рабочая база ПР9 — `db.sqlite3`.
