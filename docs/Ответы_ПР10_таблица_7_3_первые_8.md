## 5. Работа с моделями через Django Shell

**Что выполнить:**

```powershell
python manage.py shell
```

```python
from webapp.models import Visitor, Employee, Visit
Visitor.objects.all()
Employee.objects.filter(is_available=True)
visit = Visit.objects.select_related("visitor", "employee").first()
visit.visitor.full_name
visit.employee.full_name
old_status = visit.status
visit.status = Visit.Status.CANCELLED
visit.save(update_fields=["status"])
Visit.objects.get(pk=visit.pk).status
visit.status = old_status
visit.save(update_fields=["status"])
```

**Готовый ответ:** «QuerySet строится менеджером `objects`. `select_related` получает связанные объекты одним SQL-запросом. Изменение атрибута в памяти не меняет базу до `save()`, после `save(update_fields=...)` значение записывается в SQLite.»

## 6. Создание, изменение и удаление ORM-записей

**Важно:** использовать временную запись, а не реальные демонстрационные данные.

```python
temporary = Visitor.objects.create(full_name="Временный посетитель", document="TEMP")
temporary.document = "TEMP-UPDATED"
temporary.save()
Visitor.objects.get(pk=temporary.pk).document
temporary.delete()
Visitor.objects.filter(full_name="Временный посетитель").exists()
```

Последняя команда должна вернуть `False`. Объяснить назначение `create()`, `save()` и `delete()`. Для связанного посетителя удаление будет остановлено `PROTECT`.

## 7. QuerySet и несколько условий

```python
from datetime import date
from webapp.models import Visit
Visit.objects.filter(status=Visit.Status.ACTIVE, visit_date__gte=date.today())
Visit.objects.filter(status=Visit.Status.ACTIVE).order_by("visit_date")[:10]
Visit.objects.exclude(status=Visit.Status.CANCELLED)
```

**Что показать:** выполнить первый запрос, изменить условие даты на `date.min` или убрать его и показать, как изменилось количество записей.

**Готовый ответ:** «`filter()` оставляет записи, соответствующие условиям; несколько аргументов объединяются через AND. `exclude()` исключает записи. `order_by()` сортирует, а срез QuerySet реализует LIMIT.»

## 8. Фильтрация по связанным моделям

```python
Visit.objects.filter(visitor__full_name__icontains="анна")
Visit.objects.filter(employee__department="ИТ-отдел")
Visit.objects.filter(access_pass__number__startswith="P-")
```

**Что показать:** выполнить запрос с `visitor__full_name__icontains`, затем заменить имя на другое и показать изменившуюся выборку. После этого выполнить запрос по `employee__department`.

**Готовый ответ:** «Двойное подчёркивание переходит по ForeignKey к полю связанной таблицы. Django формирует JOIN автоматически. Это отличается от фильтрации только по внешнему ключу `visitor_id`, потому что здесь условие задаётся по содержимому связанного объекта.»

## Контрольные вопросы ПР10

### 1. Для чего предназначена административная панель Django?

Это готовый интерфейс управления данными моделей: просмотр, создание, изменение и удаление записей, поиск, фильтры и сортировка. В проекте она доступна по `/admin/` и работает с `Visitor`, `Employee`, `AccessPass` и `Visit`.

### 2. Как зарегистрировать модель в административной панели?

Импортировать модель в `webapp/admin.py` и использовать `@admin.register(Visitor)` перед классом `VisitorAdmin`, либо вызвать `admin.site.register(Visitor)`. После этого модель появляется в Admin.

### 3. Для чего используется `admin.ModelAdmin`?

`ModelAdmin` описывает внешний вид и поведение списка и карточки модели: столбцы, поиск, фильтры, сортировку, пагинацию, inline и оптимизацию связанных запросов.

### 4. Как с помощью `list_display` настроить столбцы?

В классе администрирования указать кортеж имён полей: `list_display = ("id", "full_name", "department")`. Эти поля появятся столбцами в списке объектов.

### 5. Чем `search_fields` отличается от `list_filter`?

`search_fields` создаёт строку поиска по текстовым полям, например имени или документу. `list_filter` создаёт фильтры по значениям поля, например `is_available`, `status` или дате.

### 6. Для чего используются `ordering` и `list_per_page`?

`ordering` задаёт сортировку списка по умолчанию, например `("full_name",)`. `list_per_page` ограничивает число строк на одной странице; в проекте установлено 20.

### 7. Как настроить отображение связанных объектов через inline?

Создать класс `admin.TabularInline` или `admin.StackedInline`, указать `model = Visit`, затем подключить его в `ModelAdmin` через `inlines = (VisitInline,)`. В проекте посещения показываются внутри посетителя и сотрудника, а пропуска — внутри посетителя.

### 8. Что такое QuerySet и когда ORM обращается к базе?

QuerySet — ленивое описание выборки Django ORM. Он обычно не выполняет SQL сразу. Запрос выполняется при итерации, `list()`, `len()`, `count()`, преобразовании в `bool()`, выводе результата или другом обращении, требующем данных.

### 9. Чем отличаются `filter()` и `exclude()`?

`filter()` оставляет записи, подходящие условию, а `exclude()` исключает записи, подходящие условию. Оба метода возвращают QuerySet и могут объединяться в цепочку.

### 10. Для чего используется объект `Q`?

`Q` позволяет строить сложные условия OR и NOT: `Visit.objects.filter(Q(status="активно") | Q(employee__is_available=True))`. Без `Q` несколько аргументов `filter()` обычно объединяются через AND.

### 11. Как отсортировать записи и ограничить выборку?

Использовать `order_by("visit_date")` или `order_by("-visit_date")`, а ограничение задать срезом: `Visit.objects.order_by("-visit_date")[:10]`.

### 12. Чем отличаются `get()` и `filter()`?

`get()` возвращает один объект и вызывает исключение, если найдено 0 или больше 1 записи. `filter()` всегда возвращает QuerySet, который может содержать 0, 1 или много объектов.

### 13. Для чего нужен `get_object_or_404()`?

Он получает объект через ORM, а если запись не найдена, автоматически возвращает HTTP 404. В проекте используется в `webapp/views.py` для карточек посетителей, сотрудников и посещений.

### 14. Чем отличаются `select_related()` и `prefetch_related()`?

`select_related()` использует SQL JOIN для связей ForeignKey и OneToOne. `prefetch_related()` выполняет отдельный запрос и объединяет результаты в Python; он подходит для обратных и много-ко-многим связей.

### 15. Как получить поля связанной модели?

В фильтрах использовать двойное подчёркивание: `Visit.objects.filter(visitor__full_name__icontains="анна")`. В объекте получить связь точкой: `visit.visitor.full_name`.

### 16. Что такое проблема N+1?

Это ситуация, когда один запрос получает список объектов, а затем отдельный запрос выполняется для каждой связанной записи. Для ForeignKey применяют `select_related`, для обратных связей и коллекций — `prefetch_related`.
