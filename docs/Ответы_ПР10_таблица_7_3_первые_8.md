# ПР10: ответы и сценарий защиты по первым 8 показателям таблицы 7.3

В методичке используются названия Room, User и Booking из учебного проекта Roomly. В моём проекте эти роли выполняют `Visitor`, `Employee` и `Visit`. Дополнительная модель `AccessPass` хранит пропуск посетителя.

## 1. Настройка административной панели

Открыть `webapp/admin.py` и показать регистрации моделей и классы `VisitorAdmin`, `EmployeeAdmin`, `AccessPassAdmin`, `VisitAdmin`. Объяснить:

- `list_display` задаёт столбцы списка;
- `search_fields` включает поиск;
- `list_filter` добавляет фильтры справа;
- `ordering` задаёт сортировку;
- `inlines` показывает связанные записи внутри карточки;
- `autocomplete_fields` позволяет искать связанные объекты.

В терминале создать администратора и запустить сервер:

```powershell
python manage.py createsuperuser
python manage.py runserver
```

Открыть `/admin/`, показать списки посетителей, сотрудников и посещений. В карточке посетителя показать inline пропусков и посещений. В карточке сотрудника показать inline посещений. Для преподавателя объяснить соответствие: Visitor = Room, Employee = User, Visit = Booking.

## 2. Работа со связанными объектами в Admin

Открыть карточку посетителя в `/admin/webapp/visitor/`. Встроенные таблицы `AccessPassInline` и `VisitInline` показывают связанные записи. Изменить цель или статус посещения, сохранить и открыть страницу посещений.

Объяснение: внешний ключ связывает строки таблиц. `related_name` обеспечивает обратный доступ в ORM, а `on_delete=PROTECT` не позволяет удалить объект, если на него ссылаются пропуск или посещение.

## 3. Изменение модели и миграции

Открыть `webapp/models.py`, изменить допустимый параметр поля, например `Visitor.document` с `max_length=80` на `max_length=100`, затем выполнить:

```powershell
python manage.py makemigrations webapp
python manage.py migrate
python manage.py showmigrations
```

Показать созданный файл миграции и отметку `[X]`. Объяснение: `makemigrations` создаёт описание изменения схемы, `migrate` применяет это описание к SQLite. После защиты можно вернуть `80` или оставить `100`; при возврате снова создать и применить миграцию.

## 4. Преобразование существующих данных при изменении модели

В текущем проекте миграция `0002_alter_visitor_document.py` изменяет ограничение длины поля без потери существующих строк. Показать файл миграции и записи посетителей в Admin.

Объяснить: если меняется формат данных, сначала создают миграцию данных с функцией преобразования старых значений, затем схему и только после проверки удаляют старое поле. Для текущего изменения преобразование значений не требуется, потому что меняется только допустимая длина строки.

## 5. Работа с моделями через Django Shell

Выполнить:

```powershell
python manage.py shell
```

Затем показать чтение, фильтрацию и изменение:

```python
from webapp.models import Visitor, Employee, Visit
Visitor.objects.all()
Employee.objects.filter(is_available=True)
visit = Visit.objects.select_related("visitor", "employee").first()
visit.visitor.full_name
visit.status = Visit.Status.CANCELLED
visit.save(update_fields=["status"])
```

Объяснить разницу между изменением объекта в памяти и сохранением через `save()`.

## 6. Создание, изменение и удаление через ORM

Использовать временную запись, не удалять демо-данные:

```python
temporary = Visitor.objects.create(full_name="Временный посетитель", document="TEMP")
temporary.document = "TEMP-UPDATED"
temporary.save()
temporary.delete()
Visitor.objects.filter(full_name="Временный посетитель").exists()
```

Результат последней команды — `False`. Объяснить, что удаление посетителя со связанным пропуском или посещением будет запрещено `PROTECT`.

## 7. QuerySet и несколько условий

Показать запрос `Visit` с несколькими условиями и изменить одно условие:

```python
from datetime import date
from webapp.models import Visit
Visit.objects.filter(status=Visit.Status.ACTIVE, visit_date__gte=date.today())
Visit.objects.filter(status=Visit.Status.ACTIVE).order_by("visit_date")[:10]
```

Объяснить, что `filter()` возвращает QuerySet, условия объединяются через AND, `order_by()` задаёт сортировку, а срез ограничивает результат.

## 8. Фильтрация по полям связанных моделей

Показать двойное подчёркивание для перехода по ForeignKey:

```python
Visit.objects.filter(visitor__full_name__icontains="анна")
Visit.objects.filter(employee__department="ИТ-отдел")
Visit.objects.filter(access_pass__number__startswith="P-")
```

Объяснить, что `visitor__full_name`, `employee__department` и `access_pass__number` обращаются к полям связанных таблиц. Django сам формирует JOIN в SQL.
